# Purser v2 — Readable Manual and Brand Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the manual readable to a human and rebuild the interface on the project's real brand, without weakening the coordinate-only citation architecture.

**Architecture:** Page furniture (letterhead, revision stamps, footers) is identified once at ingest and stored as *metadata* — a list of line indices — never by rewriting or renumbering lines. `CiteRef` coordinates stay indices into the full `Page.lines`, so the citation system is untouched. Everything downstream then filters: the agent stops reading 51% noise, citations stop quoting letterhead, and the manual browser renders a document instead of a debug dump. The interface is rebuilt on the navy/ivory/gold identity already in `assets/`.

**Tech Stack:** Python 3.12, Pydantic v2, FastAPI, SQLite (FTS5), NumPy, fastembed, React 18 + Vite + TypeScript, Docker.

**Spec:** `docs/superpowers/specs/2026-09-22-purser-design.md` (amended by Task 12)

**Binding API description:** `.superpowers/sdd/2026-09-22-purser/api-contract.md` — this file, not the v1 task briefs, describes the API as built.

## Why this plan exists — the measurement

Taken directly from `data/manual.sqlite`, all 1,226 pages:

| | lines | share |
| --- | ---: | ---: |
| blank | 19,347 | 39% |
| repeated page chrome | 6,100 | 12% |
| **actual content** | **24,276** | **49%** |

Six boilerplate patterns repeat on essentially every page (`InterGlobe Aviation Limited` ×1,229, `NOT A CONTROLLED COPY` ×1,226, `SAFETY AND EMERGENCY PROCEDURES MANUAL` ×1,223, `Issue IX Revision NN` ×1,200, `Page N of M` ×1,200, `Effective <date>` ×22).

This is not only a rendering problem. The same 51% noise is fed to the agent on every `read_page`/`read_section`, is embedded into every page vector, and leaks into citations when the model cites a wide line range.

## Global Constraints

- Python `>=3.12`. Node `>=20`. Ruff `line-length = 100`, select `E,F,I,UP,B,SIM,DTZ,FURB`. `DTZ` = timezone-aware datetimes only.
- **`CiteRef` line indices are never renumbered.** `line_from` inclusive, `line_to` **exclusive**, both indices into the full, unfiltered `Page.lines`. Chrome is metadata, not a transformation. Any change that shifts an index invalidates every stored citation in `var/app.sqlite`.
- **`CiteRef` has no `quote` field, ever.** `src/purser_api/citations.py` remains the only code that produces quote text.
- `purser_core` MUST NOT import `fastapi`, `pydantic_ai`, `openai`, `httpx`, `sqlmodel`, `starlette`. Enforced by `tests/test_boundaries.py`.
- SQLModel `table=True` models **do not validate** — `Message(role="banana")` constructs fine. Constraints must exist at the DB level.
- The SSE stream uses **CRLF**. Normalise `\r\n` → `\n` across the accumulated buffer before splitting records.
- The manual PDF is a controlled document: `docs/*.pdf` is gitignored, copied into the image at build time.
- `data/` is committed and immutable at runtime. `var/` is gitignored runtime state in a named volume.
- Model string comes from `PURSER_MODEL` via `purser_agent/provider.py`. Never hardcode a model name elsewhere.
- **Commits carry the repository owner as sole author.** No `Co-Authored-By:` trailers, no "Generated with Claude Code" footers, no AI-attribution line in any commit or PR.

```python
# src/purser_ingest/chrome.py
"""Which lines on a page are furniture rather than content.

Measured over all 1,226 pages: 6,100 lines match these six patterns, and 19,347
more are blank -- together 51% of the manual's 49,723 lines. Stripping them is
worth roughly half the agent's reading budget and is the difference between the
manual browser showing a procedure and showing letterhead.

IMPORTANT: this module returns INDICES. Nothing downstream may renumber
Page.lines. CiteRef.line_from/line_to are indices into the full list, and every
citation in var/app.sqlite would silently point somewhere else if they moved.
"""

from __future__ import annotations

import re

# Each pattern is anchored to text the manual prints as page furniture. They were
# derived by counting hits across the whole corpus, not guessed:
#   InterGlobe/ifly.SEP  1,229   NOT A CONTROLLED COPY  1,226
#   manual title         1,223   Issue N Revision NN    1,200
#   Page N of M          1,200   Effective <date>          22
_CHROME = re.compile(
    r"InterGlobe Aviation Limited"
    r"|ifly\.SEP"
    r"|NOT A CONTROLLED COPY"
    r"|SAFETY AND EMERGENCY PROCEDURES MANUAL"
    r"|Issue\s+[IVXLC]+\s+Revision\s+\d+"
    r"|Page\s+\d+\s+of\s+\d+"
    r"|Effective\s*\d{1,2}\s"
)


def chrome_line_indices(lines: list[str]) -> list[int]:
    """Indices of page-furniture lines. Blank lines are NOT chrome."""
    return [i for i, line in enumerate(lines) if line.strip() and _CHROME.search(line)]
```

```python
# append to tests/test_chrome.py
import json
import sqlite3
from pathlib import Path

import pytest

pytestmark_corpus = pytest.mark.skipif(
    not Path("data/manual.sqlite").is_file(), reason="needs the built index"
)


@pytestmark_corpus
def test_corpus_wide_counts_match_the_measurement():
    """Guards against a pattern that silently eats real content.

    These numbers were measured before the module existed. If a future edit to
    the regex starts swallowing procedure text, the content count drops and this
    goes red. Without it, over-suppression is invisible -- the UI just quietly
    shows less of the manual.
    """
    con = sqlite3.connect("data/manual.sqlite")
    total = chrome = content = 0
    empty_pages = []
    for pdf_page, raw in con.execute("select pdf_page, lines from pages order by pdf_page"):
        lines = json.loads(raw)
        idx = set(chrome_line_indices(lines))
        total += len(lines)
        chrome += len(idx)
        kept = [i for i, s in enumerate(lines) if s.strip() and i not in idx]
        content += len(kept)
        if not kept:
            empty_pages.append(pdf_page)

    assert total == 49_723
    assert chrome == 6_100
    assert content == 24_276
    assert empty_pages == [314, 338, 484, 1179, 1181, 1182, 1185, 1188]
```

```python
# src/purser_core/reading.py
from __future__ import annotations

from purser_core.corpus import Corpus
from purser_core.models import Page, ReadingPage


def _body(page: Page) -> str:
    """Content lines, verbatim, with runs of blanks collapsed to a single break.

    Leading whitespace is preserved exactly: in a procedure the indent IS the
    nesting level, and flattening it changes what the step means.
    """
    keep = {i for i, _ in page.content_lines()}
    out: list[str] = []
    blank_pending = False
    for i, line in enumerate(page.lines):
        if i in keep:
            if blank_pending and out:
                out.append("")
            blank_pending = False
            out.append(line.rstrip())
        elif not line.strip():
            blank_pending = True
    return "\n".join(out)


def reading_pages(corpus: Corpus, section: str) -> list[ReadingPage]:
    pages = corpus.pages_in_section(section)
    result: list[ReadingPage] = []
    for page in pages:
        body = _body(page)
        result.append(
            ReadingPage(
                pdf_page=page.pdf_page,
                page_in_section=page.page_in_section,
                section_total=page.section_total,
                section=page.section,
                section_title=page.section_title,
                revision=page.revision,
                effective=page.effective,
                text=body,
                empty=not body,
            )
        )
    return result
```

**Design rules, which are the deliverable as much as the code:**

1. **Two voices, never blended.** Assistant prose in `--font-ui`. Verbatim manual text in `--font-mono` behind a 3px `--cite-rule` edge. She must never have to work out which she is reading — that distinction is the entire reason the backend emits coordinates instead of quotes.
2. **Gold is the citation colour.** It appears on citation rules, the active tab underline, and focus rings. It never fills a button, never sits behind text, never becomes a gradient.
3. **No cards.** No box-shadows, no rounded panels, no identical containers. Rules and space do the structural work.
4. **One motion:** the page drawer sliding up. No entrance animations on messages, no hover transitions on everything.
5. **Never trim `Citation.text`.** Leading whitespace is load-bearing. `white-space: pre-wrap`, and run it through `displayManualText()` from `web/src/lib/manualText.ts` so the 4,341 private-use-area glyphs render as bullets rather than tofu boxes.
6. **The revision stamp stays visible on every citation.** A superseded procedure presented as current is the failure that actually endangers her.
7. **Zero citations is normal**, not an error — the general-conversation case. Mark it `Not from the manual.` in `--text-dim`.

**Risks, named.**

1. **An over-broad chrome pattern eats real content.** Guarded by the corpus-wide count test in Task 1, which pins all three totals and the exact list of 8 empty pages.
2. **Something renumbers lines and silently invalidates every citation.** This is the worst outcome available in this plan — the text would still read plausibly. Guarded by `test_content_lines_keeps_ORIGINAL_indices` (Task 2) and by `test_numbered_lines_omit_furniture_but_keep_original_numbers` (Task 3), which both check against `page.lines[i]` directly.

4. **The rebrand drifts into a generic dark theme with a gold accent.** The rule that gold touches only citation rules, the active tab and focus rings is the tripwire; if it lands on a CTA, that has happened.
