# Purser v2 — Readable Manual and Brand Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the manual readable to a human and rebuild the interface on the project's real brand, without weakening the coordinate-only citation architecture.

**Architecture:** Two independent problems sit behind one symptom. First, page furniture (letterhead, revision stamps, footers) is identified once at ingest and stored as *metadata* — a list of line indices — never by rewriting or renumbering lines. Second, the manual's text layer carries real structure (numbered headings, bulleted steps with wrapped continuations, notes, two-column tables) which a line-by-line monospace dump destroys; a parser recovers it into typed blocks. `CiteRef` coordinates stay indices into the full `Page.lines` throughout, so the citation system is untouched. The interface is then rebuilt on the navy/ivory/gold identity.

**Tech Stack:** Python 3.12, Pydantic v2, FastAPI, SQLite (FTS5), NumPy, fastembed, React 18 + Vite + TypeScript, Docker.

**Spec:** `docs/superpowers/specs/2026-09-22-purser-design.md` (amended by Task 13)

**Visual spec:** `docs/design/purser-v2-mockup.html` — the approved design, rendering real manual text. Published at <https://claude.ai/artifact/B7vu5YfTG4jBcezckboWuv>. **Where this plan's prose and the mockup disagree about appearance, the mockup wins.** Open it before starting any Phase C or D task.

**Binding API description:** `.superpowers/sdd/2026-09-22-purser/api-contract.md` — the API as built. The v1 task briefs predate the backend and are wrong about the tool event, the citations payload shape, delta granularity, thread field names, the health payload and the line endings.

## Why this plan exists — the measurements

**1. Half of what we render is furniture.** Counted over all 1,226 pages in `data/manual.sqlite`:

| | lines | share |
| --- | ---: | ---: |
| blank | 19,347 | 39% |
| repeated page chrome | 6,100 | 12% |
| **actual content** | **24,276** | **49%** |

Six patterns repeat on essentially every page: `InterGlobe Aviation Limited` ×1,217, `NOT A CONTROLLED COPY` ×1,226, `SAFETY AND EMERGENCY PROCEDURES MANUAL` ×1,223, `Issue IX Revision NN` ×1,200, `Page N of M` ×1,200 (zero unique hits; kept as insurance against future footer changes), `Effective <date>` ×1,222 (marginal: ×22 not caught by other patterns).

**2. The text is structured, and we throw the structure away.** From pdf_page 552:

```
 12 ind=0   2. CREW RESPONSIBILTIES                                      <- numbered heading
 14 ind=5   ▸ Inform the PIC immediately of the source, colour, density of the
 16 ind=9     smoke (if present), and its effects on passengers.         <- WRAPPED CONTINUATION
 24 ind=4   Note: Kindly refer to PART THREE for details                 <- note
 26 ind=34  Table 4.2B                                                   <- caption
 27 ind=10  MID AIR SMOKE FILLED CABIN      CABIN CREW ACTIONS           <- genuine two columns
```

Line 16 is the back half of line 14's sentence. Rendered line-by-line it becomes an orphan, which is why the manual reads as though it were scanned. There are thousands of these.

**3. The section reader shows one page of eighty.** `web/src/components/TocBrowser.tsx` requests `Math.min(4, …)` pages and then renders `.slice(0, 40)` lines. §4.4 has 80 pages. The API is correct — verified returning 8, 80 and 74 pages for §4.2, §4.4 and §1.1. The component is a preview where a reader is needed.

## Global Constraints

- Python `>=3.12`. Node `>=20`. Ruff `line-length = 100`, select `E,F,I,UP,B,SIM,DTZ,FURB`. `DTZ` = timezone-aware datetimes only.
- **`CiteRef` line indices are never renumbered.** `line_from` inclusive, `line_to` **exclusive**, both indices into the full, unfiltered `Page.lines`. Chrome is metadata; blocks are a derived view. Any change that shifts an index invalidates every citation stored in `var/app.sqlite`, and the resulting text would still read like plausible manual prose — which is what makes it the worst available failure.
- **`CiteRef` has no `quote` field, ever.** `src/purser_api/citations.py` remains the only code that produces quote text, and `Citation.text` remains the byte-exact splice even after `Citation.blocks` is added.
- `purser_core` MUST NOT import `fastapi`, `pydantic_ai`, `openai`, `httpx`, `sqlmodel`, `starlette`. Enforced by `tests/test_boundaries.py`.
- SQLModel `table=True` models **do not validate** — `Message(role="banana")` constructs fine. Constraints must exist at the DB level.
- The SSE stream uses **CRLF**. Normalise `\r\n` → `\n` across the accumulated buffer before splitting records.
- The manual PDF is a controlled document: `docs/*.pdf` is gitignored, copied into the image at build time.
- `data/` is committed and immutable at runtime. `var/` is gitignored runtime state in a named volume.
- Model string comes from `PURSER_MODEL` via `purser_agent/provider.py`. Never hardcode a model name elsewhere.
- **Commits carry the repository owner as sole author.** No `Co-Authored-By:` trailers, no "Generated with Claude Code" footers, no AI-attribution line in any commit or PR.

# src/purser_ingest/chrome.py
"""Which lines on a page are furniture rather than content.

IMPORTANT: this module returns INDICES. Nothing downstream may renumber
Page.lines. CiteRef.line_from/line_to are indices into the full list, and every
citation in var/app.sqlite would silently point somewhere else if they moved --
while still splicing text that reads like plausible manual prose.
"""

from __future__ import annotations

import re

# Derived by counting hits across the whole corpus, not guessed:
#   InterGlobe/ifly.SEP  1,229   NOT A CONTROLLED COPY  1,226
#   manual title         1,223   Issue N Revision NN    1,200
#   Page N of M          1,200   Effective <date>          22
_CHROME = re.compile(
    r"InterGlobe Aviation Limited"
    r"|ifly\.SEP"
    r"|NOT A CONTROLLED COPY"
    r"|SAFETY AND EMERGENCY PROCEDURES MANUAL"
    r"|Issue\s+[IVXLC]+\s+Revision\s+\d+"
    r"|Page\s+\d+\s+of\s+\d+"
    r"|Effective\s*\d{1,2}\s"
)


def chrome_line_indices(lines: list[str]) -> list[int]:
    """Indices of page-furniture lines. Blank lines are NOT chrome."""
    return [i for i, line in enumerate(lines) if line.strip() and _CHROME.search(line)]
```

import json
import sqlite3
from pathlib import Path

import pytest

needs_index = pytest.mark.skipif(
    not Path("data/manual.sqlite").is_file(), reason="needs the built index"
)


@needs_index
def test_corpus_wide_counts_match_the_measurement():
    """Guards against a pattern that silently eats real content.

    These numbers were measured before the module existed. If a future edit to
    the regex starts swallowing procedure text, the content count drops and this
    goes red. Without it, over-suppression is invisible -- the UI just quietly
    shows less of the manual than it used to.
    """
    con = sqlite3.connect("data/manual.sqlite")
    total = chrome = content = 0
    empty_pages = []
    for pdf_page, raw in con.execute("select pdf_page, lines from pages order by pdf_page"):
        lines = json.loads(raw)
        idx = set(chrome_line_indices(lines))
        total += len(lines)
        chrome += len(idx)
        kept = [i for i, s in enumerate(lines) if s.strip() and i not in idx]
        content += len(kept)
        if not kept:
            empty_pages.append(pdf_page)

    assert total == 49_723
    assert chrome == 6_100
    assert content == 24_276
    assert empty_pages == [314, 338, 484, 1179, 1181, 1182, 1185, 1188]
```

```python
# src/purser_core/blocks.py
"""Recover the manual's structure from its text layer.

`pdftotext -layout` preserves position, so headings, bullet nesting, notes and
two-column tables are all still present as indentation and glyphs -- they are
simply invisible if you render the lines one at a time in a monospace font.

The one judgement call is rejoining wrapped lines. A line is treated as the
continuation of the block above it only when the line above RAN TO THE COLUMN
LIMIT, measured per page. That is what distinguishes a hard-wrapped sentence
from a short standalone line, and without it the parser swallows the next
heading every time.
"""

from __future__ import annotations

import re

from purser_core.models import Block

# The manual's bullets are symbol-font glyphs in the Unicode private use area.
BULLET_GLYPHS = "•"
_NUM_HEAD = re.compile(r"^(\d+(?:\.\d+)*)\.\s+\S")
_NOTE = re.compile(r"^(Note|Caution|Warning|NOTE|CAUTION|WARNING)\s*[:\-]\s*\S")
_TABLE_CAP = re.compile(r"^Table\s+[\d.]+\s*[A-Z]?\s*$", re.IGNORECASE)


def parse_blocks(lines: list[str], chrome: list[int]) -> list[Block]:
    skip = set(chrome)
    body = [(i, s) for i, s in enumerate(lines) if i not in skip]

    widths = sorted(len(s.rstrip()) for _, s in body if s.strip())
    # 70th percentile, not the max: one wide table row would otherwise set the
    # bar so high that no prose line ever counts as wrapped.
    full = (widths[int(len(widths) * 0.70)] - 4) if widths else 0

    out: list[Block] = []
    open_indent: list[int | None] = []  # parallel to out; None once a block is closed
    prev_len = 0
    in_table = False
    table: list[str] = []

    def close_table() -> None:
        nonlocal in_table, table
        if table:
            while table and not table[0].strip():
                table.pop(0)
            while table and not table[-1].strip():
                table.pop()
            out.append(Block(kind="table", text="\n".join(table)))
            open_indent.append(None)
        in_table, table = False, []

    def add(kind: str, text: str, indent: int | None, level: int = 0) -> None:
        out.append(Block(kind=kind, level=level, text=text))
        open_indent.append(indent)

    for _, raw in body:
        stripped = raw.strip()
        indent = len(raw) - len(raw.lstrip())

        if not stripped:
            if in_table:
                table.append("")
            prev_len = 0  # a blank line always ends a wrapped run
            continue

        if _TABLE_CAP.match(stripped):
            close_table()
            add("caption", stripped, None)
            in_table = True
            prev_len = 0
            continue

        head = _NUM_HEAD.match(stripped)
        if head and indent <= 2:
            close_table()
            add("heading", stripped, None, head.group(1).count(".") + 1)
            prev_len = len(raw.rstrip())
            continue

        if in_table:
            table.append(raw.rstrip())
            continue

        if stripped[0] in BULLET_GLYPHS:
            add("bullet", stripped[1:].strip(), indent, max(0, indent // 5 - 1))
            prev_len = len(raw.rstrip())
            continue

        if _NOTE.match(stripped):
            add("note", stripped, indent)
            prev_len = len(raw.rstrip())
            continue

        if out and open_indent[-1] is not None and prev_len >= full:
            prev_ind = open_indent[-1]
            if out[-1].kind in ("bullet", "para", "note") and indent >= prev_ind:
                out[-1].text = f"{out[-1].text} {stripped}".strip()
                prev_len = len(raw.rstrip())
                continue

        if stripped.isupper() and len(stripped) < 62:
            add("subheading", stripped, indent)
        else:
            add("para", stripped, indent)
        prev_len = len(raw.rstrip())

    close_table()
    return out
```

from __future__ import annotations

from purser_core.blocks import BULLET_GLYPHS, parse_blocks
from purser_core.corpus import Corpus
from purser_core.models import ReadingPage


def reading_pages(corpus: Corpus, section: str) -> list[ReadingPage]:
    out: list[ReadingPage] = []
    for page in corpus.pages_in_section(section):
        blocks = parse_blocks(page.lines, page.chrome)
        out.append(
            ReadingPage(
                pdf_page=page.pdf_page,
                page_in_section=page.page_in_section,
                section_total=page.section_total,
                section=page.section,
                section_title=page.section_title,
                revision=page.revision,
                effective=page.effective,
                blocks=blocks,
                empty=not blocks,
            )
        )
    return out

## Self-review

**Coverage.** Furniture → Tasks 1–5. Structure → Tasks 6–7, 10. Brand and depth → Task 8. Frosted chrome and the segmented control → Task 9. Chat bubbles and the paper extract → Task 11. The 4-page/40-line reader bug → Task 12. Drawer → Task 13. Icons and the README banner → already shipped in `c6cdbb7`.

**Type consistency.** `chrome_line_indices` (1) → `Page.chrome` (2) → `Page.content_lines()` (3, 4, 6) → `parse_blocks` (6) → `Block` (6) → `ReadingPage.blocks` and `Citation.blocks` (7) → `Block` in TS (10) → `<ManualBlocks>` (10, 11, 12). One name per concept throughout.

**Risks, named.**

1. **The block parser drops a line it does not recognise.** She would never know a step was missing. Guarded by `test_no_content_is_lost_anywhere_in_the_corpus`, which probes the first three words of every content line across six pages.
2. **The continuation rule swallows a following heading.** Guarded by `test_a_short_line_is_NOT_swallowed_as_a_continuation` and mutation-checked both directions in Task 6 Step 6.
3. **Something renumbers lines and silently invalidates every citation.** The worst outcome available here, because the spliced text would still read plausibly. Guarded by `test_content_lines_keeps_ORIGINAL_indices` (2) and `test_numbered_lines_omit_furniture_but_keep_original_numbers` (3), both checking against `page.lines[i]` directly.
4. **Blocks and `Citation.text` drift apart.** `text` is the guarantee; blocks are presentation. Task 7 Step 5 asserts both are present and that the words agree.
5. **An over-broad chrome pattern eats real content.** Guarded by the corpus-wide count test in Task 1.
6. **Re-embedding degrades ranking.** Task 5 is gated on MRR and reverts by default, including when recall holds but MRR drops.
7. **The rebrand drifts into a generic dark theme with a gold accent.** The tripwire: gold appears on the manual's edge, the active tab, focus rings and the send key — nowhere else. If it lands on a secondary button, that has happened.
